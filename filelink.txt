# FileLink AI — Complete Implementation Specification

## 1. PROJECT CONTEXT

This is the existing FileLink project.

The project already contains:

* React + TypeScript
* TanStack Start
* Supabase
* `src/lib/linkClient.ts`
* `src/lib/link.server.ts`
* `public/filelink.mjs`
* existing device authentication
* device online/offline detection
* `device_rpc`
* `rpcPoll`
* `rpcRespond`
* `rpcChunk`
* `rpcStatus`
* streamed remote shell execution
* remote file listing
* remote file search
* remote file read
* remote file write
* remote mkdir
* remote system information
* remote process/task information
* remote screenshot
* clipboard
* device controls
* file transfers
* offline file delivery

DO NOT replace the existing FileLink architecture.

Extend it.

The new AI system must use the existing FileLink device/RPC infrastructure rather than creating a second unrelated remote-control system.

# 8. LIVE STREAMING

Use the existing streamed RPC system.

The existing project already has:

rpcExec
rpcChunk
rpcStatus

Do not create a second shell streaming system.

When the AI launches a command:

1. Create action
2. Start RPC
3. Poll status
4. Stream chunks into the UI
5. Display stdout/stderr live
6. Finish action
7. Send result back to AI
8. Let AI decide the next step

Do NOT wait until the whole task finishes before showing output.

# 11. ERROR UNDERSTANDING

This is one of the most important features.

If a command fails:

Example:

npm run build

Output:

Module not found:
Can't resolve './components/Test'

The UI should show:

✕ Command failed

Error detected

Module not found:
./components/Test

Then:

AI analysis

"The build failed because the imported component does not exist."

Then the AI should determine whether it can safely fix it.

Possible flow:

1. Read relevant file
2. Inspect directory
3. Find similarly named component
4. Determine correct import
5. Propose fix
6. Ask confirmation if needed
7. Edit file
8. Re-run build
9. Verify
10. Report success

The AI should not merely say "there is an error."

It should diagnose and attempt a repair when the user requested a fix.

# 60. AI SYSTEM PROMPT

Create a strong system prompt.

Core behavior:

"You are FileLink AI, a computer-management assistant operating through the FileLink application.

You do not directly access computers. You use FileLink tools.

Always inspect the target device before making assumptions.

Use the smallest number of operations necessary.

When the user asks to diagnose a problem, inspect evidence before proposing a cause.

When the user asks to fix a problem, attempt a safe repair and verify it.

Never claim an operation succeeded until the device reports success.

Never fabricate command output, files, paths, device status, or results.

If a device is offline, do not pretend to execute the operation.

Create a persistent queued task when the user wants the operation performed when the device returns.

If an operation is dangerous, destructive, requires administrator permission, replaces an existing file, or exposes sensitive information, request explicit confirmation.

When an operation fails, analyze the actual error and decide whether a safe repair is possible.

After making a change, verify the result.

For multiple devices, process them independently and clearly separate their results.

Be concise in the final answer but provide technical details in expandable execution cards."

# 66. PROVIDER RECOMMENDATION

Make the application provider-independent.

For the first implementation, support OpenAI and Anthropic.

OpenAI's current API documentation identifies GPT-5.6 Sol as its flagship model for complex reasoning and coding and supports functions, file search, web search and computer-use capabilities.

Anthropic's current documentation describes current Claude models as suitable for tool use and agentic systems and specifically discusses long-horizon reasoning, tool use, and document/presentation creation.

Recommended configuration:

AI_PROVIDER=openai
AI_MODEL=gpt-5.6-sol

Allow changing this later to an Anthropic model without changing the FileLink architecture.

Do NOT expose the provider choice as a requirement for the user.
